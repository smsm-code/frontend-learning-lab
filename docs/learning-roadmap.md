| | |
|---|---|

## 全体像

```
Phase 0 ─ 環境構築と基礎の整地(1〜2週間)
   │        Zed / Git / このリポジトリ自体の運用開始
Phase 1 ─ 静的〜小規模SPA(3〜4週間)
   │        ポートフォリオ + 小物アプリ / 初めてのGCPデプロイ(静的)
Phase 2 ─ フルスタックCRUDアプリ(6〜8週間)
   │        SvelteKitの核心(load/フォームアクション)/ DB / 認証 / Cloud Run
Phase 3 ─ 品質エンジニアリング(4〜6週間)
   │        テスト / CI / a11y / 監視 / パフォーマンス改善を「後付け」する
Phase 4 ─ プロの入口(継続)
            OSS / 発信 / React・Next.js比較学習 / 市場との接続
```

**進め方の原則**

1. **作りながら学ぶ**: 各Phaseは「作るもの」が主役。知識は必要になった瞬間に取りに行く
2. **螺旋的に深める**: 同じテーマ(SSR、状態管理、HTTP)に各Phaseで繰り返し出会い、少しずつ深くする
3. **「動いた」で終わらせない**: 動いたら「なぜ動くのか」を一段だけ掘る。これがチェックリストのL2→L3を作る
4. **常にPR経由**: 個人開発でもブランチ→PR→セルフレビュー→マージ。実務との差を消す
5. **情報の鮮度を確認**: Svelte 4以前・Tailwind v3前提の記事が大量に残っている。公式ドキュメントを一次情報とする

## Phase 0: 環境構築と基礎の整地(1〜2週間)

### ゴール
開発環境が整い、Svelte 5の基本文法とTSの基礎を一周し、**この2文書をGitHubリポジトリで運用開始**している。

### 実践課題

**課題0-1: 学習管理リポジトリの作成(最初のタスク)**
- GitHubにリポジトリを作り、`tech-stack-checklist.md` と本文書を配置
- 以後、チェックリストのレベル更新・文書の改訂はすべてブランチ→PR→マージで行う(Git練習を兼ねる)
- READMEに学習の目的と現在地を書く

**課題0-2: Zed環境の構築**
- Zed本体 + Svelte拡張のインストール
- settings.json にTailwind LSPの設定を追加(SvelteファイルでTailwind補完を効かせる):

```json
{
  "lsp": {
    "svelte-language-server": {
      "initialization_options": {}
    },
    "tailwindcss-language-server": {
      "settings": {
        "includeLanguages": { "svelte": "html" }
      }
    }
  }
}
```

- Prettier連携を確認し、`.prettierrc` に `prettier-plugin-tailwindcss` を追加(クラス名自動整列)
- Node.js(LTS)+ pnpm のセットアップ

**課題0-3: GCPアカウントの初期設定**
- プロジェクト作成、課金アカウント設定
- **予算アラートを最初に設定する**(学習用: 月額上限の目安を決めて通知)
- gcloud CLI のインストールと認証

**課題0-4: 基礎学習**
- Svelte公式チュートリアル(svelte.dev/tutorial)を**全部**やる。Runes対応済みで業界屈指の品質。これが最短経路
- TypeScript Handbook相当の基礎(型 / ユニオン / ジェネリクス / narrowing)を並行

### このPhaseで埋めるチェックリスト項目
`6-1〜6-6`(開発環境)、`2-1, 2-5, 2-6`(TS/Svelte基礎)、`5-1`(GCP基礎)

### 卒業条件
- チュートリアル完走、かつ簡単なコンポーネント(カウンター、リスト表示)を何も見ずに書ける
- PRを1つ以上マージした

## Phase 1: 静的〜小規模SPA(3〜4週間)

### ゴール
SvelteKit + Tailwind v4 でサイトを構築し、GCPに静的デプロイまで完了する。

### 実践課題

**課題1-1: ポートフォリオサイト**
- `npx sv create` でプロジェクト作成(TypeScript / ESLint / Prettier / Tailwind を選択)
- 内容: 自己紹介、スキル(チェックリストと連動)、制作物一覧、学習ログ
- 学ぶこと: コンポーネント分割、`$props()` の型付け、レイアウト(`+layout.svelte`)、Tailwindのレスポンシブ・ダークモード(`@custom-variant`)

**課題1-2: インタラクティブな小物を2〜3個**
- 例: ToDo(`$state` / `$derived` の練習)、ポモドーロタイマー(`$effect` とクリーンアップ)、電卓(判別可能ユニオンでの状態モデリング)
- ポートフォリオ内のページとして組み込む

**課題1-3: GCPへの静的デプロイ**
- `adapter-static` でprerenderし、**Firebase Hosting**へデプロイ(静的サイトの最速経路)
- 学ぶこと: SSGとは何か、CDNキャッシュの基本、独自ドメイン設定(任意)
- 発展: Cloud Storage + Cloud CDN 構成との違いを調べて比較メモを書く

### このPhaseで埋めるチェックリスト項目
`1-1〜1-3, 1-9`(HTML/CSS/DevTools)、`2-7, 2-9, 2-10`(コンパイラ理解/Tailwind)、`3-1, 3-4`(ルーティング/SSG)、`5-5`(Firebase Hosting)、`6-3, 6-4`(Git/GitHub Flow)

### 卒業条件
- 公開URLを持つポートフォリオが存在する
- 「Svelteはなぜ速いのか」を自分の言葉で説明した文章(ブログ/README)を書いた

## Phase 2: フルスタックCRUDアプリ(6〜8週間)

### ゴール
実データ・認証・DBを備えたアプリを構築し、**Cloud Runで本番稼働**させる。SvelteKitのデータフローの核心を体得する。

### 実践課題

**課題2-1: テーマ選定と設計**
- 例: 読書記録、家計簿、ブックマーク管理、筋トレログ。**自分が使い続けたいもの**を選ぶ(改善動機が続く)
- 実装前に: 画面一覧、データモデル、URL設計をMarkdownで書く(設計を言語化する練習)

**課題2-2: データフローの実装**
- `load` 関数(server / universal の使い分けを意識的に)
- フォームアクション + Progressive Enhancement(`use:enhance`)。まずJSなしで動くことを確認してから拡張する
- Zod(またはValibot)+ superforms でバリデーション。「境界で検証する」原則を体で覚える

**課題2-3: UIをshadcn-svelteで構築**
- CLIでコンポーネント導入後、**Bits UIのソースを読む**(フォーカス管理・ARIA属性がどう実装されているか)
- `cn()`(clsx + tailwind-merge)の役割を理解して使う

**課題2-4: DBと認証**
- DB: ローカルはSQLite + Drizzle ORM → 本番は Cloud SQL(PostgreSQL)へ。Drizzleなら方言差の吸収を体験できる
  - コスト注意: Cloud SQLは常時起動課金。学習中はインスタンスを停止する運用、または開発中はSQLiteのままでも可
- 認証: まずセッション認証の仕組み(Cookie / セッションストア)を調べて最小実装を試み、その後 Better Auth か Identity Platform に置き換える。「理解してから楽をする」順序を守る

**課題2-5: Cloud Runへのデプロイ**
- `adapter-node` に切り替え、Dockerfile(マルチステージビルド)を書く
- Artifact Registry にイメージをpushし、Cloud Runへデプロイ(まずは `gcloud run deploy` 手動で)
- Secret Manager で環境変数(DB接続情報等)を管理。「秘密をクライアントに出さない」構成を確認
- 学ぶこと: コールドスタート、スケールtoゼロ、同時実行数、リビジョンとトラフィック分割

### このPhaseで埋めるチェックリスト項目
`3-2, 3-3, 3-5〜3-8, 3-12〜3-14`(SvelteKit核心/DB/認証)、`3-9, 3-10`(shadcn-svelte)、`2-2, 2-3`(TS設計)、`5-2〜5-4, 5-7, 5-8`(Cloud Run/Docker/Secret Manager)、`1-5, 1-6`(イベントループ/HTTP — 実装中に必ず必要になる)

### 卒業条件
- Cloud Run上で動く公開アプリがあり、認証・CRUD・バリデーションが機能している
- 「このページはなぜSSR(またはSSG)なのか」を全ページについて説明できる

## Phase 3: 品質エンジニアリング(4〜6週間)

### ゴール
Phase 2のアプリに品質パイプラインを**意図的に後付け**し、「なぜ最初から入れるべきか」を苦労とともに体感する。

### 実践課題

**課題3-1: テストの導入**
- Vitest: ユーティリティ関数・バリデーションロジックのユニットテスト
- Testing Library: 主要コンポーネントを「ユーザー視点」でテスト
- Playwright: 最重要フロー(ログイン→主要操作→ログアウト)のE2Eを2〜3本。**多くは書かない**(テスト戦略の実践)
- MSW: 外部APIがあればネットワーク境界でモック化し、テスト/開発で共有

**課題3-2: CIの構築**
- GitHub Actions: PRごとに lint / svelte-check / test / build
- 発展: Workload Identity連携でGitHub Actions→Cloud Runの自動デプロイ(サービスアカウントキーを使わない構成の意味を理解する)

**課題3-3: アクセシビリティ監査**
- キーボードだけで全機能を操作してみる → 発見した問題を修正
- スクリーンリーダー(macOSならVoiceOver)で主要フローを試す
- @axe-core/playwright をE2Eに組み込み、自動検査を常設化

**課題3-4: パフォーマンスと監視**
- Lighthouse計測 → Core Web Vitals(LCP/INP/CLS)の改善を**数値の前後付きで**記録(画像最適化、フォント、コード分割)
- Sentry導入(クライアントエラー)+ Cloud Logging/Error Reporting(サーバー側)。役割分担を理解する
- わざとエラーを仕込み、通知→原因特定→修正の一連を体験する

**課題3-5: セキュリティ点検**
- XSS: `{@html}` の使用箇所を監査。CSPヘッダを設定してみる
- SvelteKitのCSRF対策の仕組みを調べ、自分の言葉でまとめる

### このPhaseで埋めるチェックリスト項目
`4-1〜4-10`(品質保証ほぼ全部)、`5-9, 5-11〜5-13`(CI/CD・監視・Web Vitals)、`1-4`(レンダリングパイプライン — パフォーマンス改善で必要になる)

### 卒業条件
- PRを出すとCIが回り、マージすると自動デプロイされる状態
- Lighthouse改善のビフォーアフターを記事化した

## Phase 4: プロの入口(継続)

### ゴール
市場と接続する。「作れる」から「プロとして信頼される」への移行。

### 実践課題(並行して継続的に)

**課題4-1: React / Next.js の比較学習(2〜4週間の集中)**
- React基礎(コンポーネント / hooks / JSX)→ Next.js(App Router)で小さなアプリを1つ
- 成果物: **SvelteKit ⇔ Next.js 概念対応表**を自分で書く(ルーティング、データ取得、フォーム、レンダリング戦略)
- 目的: 求人市場の現実(React求人が最多)への備えと、「なぜSvelteを選んだか」を比較で語れる状態を作ること
- 注意: RunesとhooksはリアクティビティモデルがReactと根本的に異なる(シグナル vs 再レンダリング)。混乱したらこの違いに立ち返る

**課題4-2: OSS貢献**
- 入口: shadcn-svelteやSvelte本体のドキュメント修正、Issueの再現確認から
- 学ぶこと: 再現手順の書き方、メンテナとのコミュニケーション、他人のコードベースを読む力

**課題4-3: 技術発信の定常化**
- 各Phaseの学びをZenn等で記事化。「Svelte 5 + Tailwind v4 + GCP」の日本語情報は不足しており、書くだけで価値がある
- 記事執筆=チェックリストL3到達の検証手段と位置づける

**課題4-4: 模写と分解**
- 実在サービスのUIをshadcn-svelteで再現する
- 既存OSSのSvelteKitアプリをコードリーディングし、設計判断を推測してメモする

**課題4-5: 必要に応じた拡張**
- モノレポ(Turborepo)、Storybook + 視覚回帰、i18n、PWA — 「必要になったら」の原則で

### このPhaseで埋めるチェックリスト項目
`7-1〜7-4`(React/Next.js/OSS/発信)、残りの○項目のL2→L3化

## 日常の習慣(全Phase共通)

- **一次情報の定期購読**: 「What's new in Svelte」(月次)、Tailwind公式ブログ、State of JS(年次)。チェックリストの四半期見直しとセットで
- **インプット:アウトプット = 3:7**: チュートリアル消化より「自分の課題を自分で作って解く」時間を多く
- **AIの使い方**: 学習初期は自力で書いてからAIの案と比較する。生成コードを鵜呑みにせず、レビューする側の目を育てる
- **新ツール評価の3点**: どの課題を解くのか / 何を置き換えるのか / 採用実績と保守状況は
- **記録を残す**: 詰まった点と解決をリポジトリのログに書く。未来の自分と記事の素材になる

## つまずいたときの指針

- 情報が古い可能性を疑う(Svelte 4 / Tailwind v3 前提の記事ではないか)
- 公式ドキュメント → GitHub Issues/Discussions → コミュニティの順で当たる
- 30分詰まったら問題を言語化して書き出す(それ自体が解決策になることが多い)
- 完璧主義に注意: 各Phaseの卒業条件を満たしたら先へ進む。螺旋的にまた戻ってくる
